프로젝트 소개

관리자가 작업을 등록하면 작업자에게 알림톡이 나가고, 작업자가 휴대전화에서 안전 내용을 확인하고 완료 보고를 하면 그 기록이 자동으로 남는 흐름을 90일 안에 완성합니다. 법정 일지·점검서류는 항목 단위로 추적·검증하고, 납품 후 월 단위 서버 운영까지 맡습니다.

핵심 요구사항 분석

  • 사용자·권한: 관리자·작업관리자·안전관리자·협력업체·작업자 5종 역할, 고객사·현장별 정보와 권한 분리 (멀티테넌트)
  • 사용 환경: 관리자는 PC 웹, 작업자는 카카오 알림톡 링크로 여는 모바일 웹 (앱 설치 없음)
  • 핵심 흐름: 작업 등록·배정 → 알림톡(작업 내용 + 착용 안전장비) → 작업자 안전 확인·개인별 승인 → 업체 작업관리자 승인 → 작업 시작 → 완료 보고 → 기록 자동 보관
  • 작업허가: 협력업체가 보수작업 신청서·작업자 명단·위험성평가 제출 → 담당자 검토 → 승인 또는 보완 요청
  • 안전서류: 작업 전 안전회의(TBM), 교육, 점검 일지와 확인 기록 보관, 엑셀·파일 묶음(ZIP) 내려받기
  • 기타: 긴급 보수작업 접수·담당자 알림·조치 결과 기록, 공지사항·비상연락망, 진행 현황 대시보드
  • 인프라·운영: 테스트·운영 서버 구성, 납품 이후 월 단위 서버 운영 (하루 약 100명)
  • 결과물: 전체 소스코드(발주사 소유), DB 스키마, 화면 설계서, 기본 운영 안내 문서, 테스트·운영 서버 배포
  • 우선순위: 1순위 산출물 완성도 → 2순위 금액 → 3순위 일정 준수 / 가장 큰 우려: 법정 일지·서류 항목 누락

제안 포인트

1. 참고 서비스(어깨동무M) 흐름 분석 결과 반영

  • 참고하신 서비스는 카카오톡 기반으로 앱 설치 없이 작업 알림·안전 공지·출입 확인을 전달하고, 협력업체 작업지시서도 서면·이메일 대신 시스템으로 발부·수령해 이력을 통합 관리하는 구조로 알려져 있습니다.
  • 이번 서비스도 같은 원칙으로 "작업자는 링크 하나로 끝, 관리자는 PC에서 전체 이력 확인"을 목표로 설계합니다. 작업자 화면은 큰 버튼과 단계형 체크(안전장비 착용 확인 → 위험 요소 확인 → 서명)로 장갑을 낀 현장에서도 쓰기 쉽게 만듭니다.
  • 작업자는 별도 회원가입 없이 일회용 보안 링크 + 휴대전화 뒷자리 확인으로 본인을 확인하고, 확인·서명 시각과 단말 정보가 자동 기록되어 사후 증빙으로 쓸 수 있습니다.

2. 법정 일지·점검서류 QC와 테스트 계획 (가장 중요하게 보신 부분)

"나중에 이 항목이 빠져 있다"는 상황은 대부분 양식 → 화면 → 저장 → 출력으로 옮기는 과정에서 사람이 손으로 옮기다 생깁니다. 이 과정을 추적표와 자동 검사로 바꿔 누락을 구조적으로 막습니다.

단계방법산출물
① 항목 추적표 (RTM)전달받은 모든 양식의 모든 항목에 고유 번호(예: TBM-012)를 부여하고, 각 항목이 화면 필드 · DB 컬럼 · 엑셀 출력 셀 · 테스트 케이스 중 어디에 대응하는지 1:1로 연결합니다.서류 항목 추적표 (엑셀)
② 설계 단계 승인Day 21에 추적표와 화면 설계서를 함께 검토받습니다. 안전관리 담당자분이 항목별로 확인·서명하면 개발 기준선으로 확정합니다.항목 매핑 승인본
③ 양식을 데이터로 관리일지·서류 항목을 코드에 직접 박지 않고 양식 정의(항목명·입력 유형·필수 여부·선택지·작성 주체·서명 필요 여부)로 관리합니다. 화면·저장·엑셀 출력이 모두 같은 정의에서 만들어지므로 한 곳에만 있고 다른 곳에 빠지는 일이 생기지 않습니다.양식 정의 파일 (버전 관리)
④ 항목 커버리지 자동 테스트코드가 바뀔 때마다 "정의된 모든 항목이 입력 화면에 있는가 / 저장되는가 / 엑셀에 출력되는가 / 필수 항목 없이 제출이 막히는가"를 자동으로 검사합니다. 하나라도 빠지면 배포가 중단됩니다.CI 자동 테스트
⑤ 출력물 대조 테스트샘플 데이터로 만든 엑셀·ZIP 출력물을 원본 양식과 셀 단위로 비교합니다. 첨부자료(사진·서명)가 묶음 파일에 빠짐없이 들어갔는지도 함께 확인합니다.출력 대조 리포트
⑥ 단계별 검수Day 75 베타 때 항목 커버리지 리포트 v1, Day 90 납품 때 최종 리포트(항목 100% 대응 확인)를 함께 제출합니다. 리포트는 양식별로 "정의 항목 수 / 구현 항목 수 / 테스트 통과 수"를 보여 줍니다.항목 커버리지 리포트
⑦ 기록 무결성서명·승인 완료된 기록은 수정할 수 없고, 정정이 필요하면 정정 이력(누가·언제·무엇을·왜)으로 남깁니다. 양식이 바뀌어도 과거 기록은 작성 당시 양식 버전 그대로 보관합니다.변경 이력 테이블

추가로 현장 시범 운영(Day 76–83) 기간에 실제 작업 1~2건을 처음부터 끝까지 시스템으로 처리해 보고, 종이 서류와 나란히 비교하는 대조 점검을 진행합니다.

3. [미정 범위 1] 안전 일지·점검서류 양식 전달 방식 — 권장안과 비용 차이

  • 권장: 현재 쓰시는 원본 양식(엑셀·한글·스캔 무엇이든) + 저희가 드리는 "항목 정의서" 엑셀 템플릿을 함께 주시는 방식입니다. 템플릿 열: 양식명 / 항목명 / 입력 유형(텍스트·선택·체크·날짜·사진·서명) / 필수 여부 / 선택지 / 작성 주체(작업자·작업관리자·안전관리자 등) / 근거 법령·사내 규정 / 보존 기간.
  • 항목 정의서가 채워지면 그대로 양식 정의 파일로 변환되어 개발이 빨라지고, 추적표의 기준이 됩니다. 작성은 착수 2주 차 워크숍에서 저희가 함께 채워 드립니다.
전달 방식내용비용
A. 원본 양식 + 항목 정의서 (권장)양식 10종(TBM, 안전교육, 일일·정기 점검, 작업허가 신청서, 작업자 명단, 위험성평가, 긴급작업 조치 기록 등) 이내기본 견적 포함
B. 원본 양식만 전달저희가 원본에서 항목을 추출·정리하고 담당자 확인을 받는 작업 추가양식 1종당 +150,000원
C. 양식 10종 초과추가 양식 정의·화면·출력·테스트양식 1종당 +200,000~400,000원 (항목 수 기준)

4. [미정 범위 2] 기술 스택 제안과 선택 이유

영역제안선택 이유
백엔드Python · Django + Django REST Framework선호하신 Python 계열 중 인증·권한·DB 마이그레이션·관리 기능이 기본 내장된 가장 보편적인 프레임워크입니다. 역할별 권한과 서류·이력 데이터가 많은 업무 시스템에 적합하고, 국내 개발자 수급이 쉬워 운영 이관 후 유지보수가 편합니다.
프론트엔드React + TypeScript (Vite)말씀하신 React 방향 그대로. 관리자 PC 화면과 작업자 모바일 화면을 하나의 코드베이스에서 화면 경로로 나눠 관리 부담을 줄입니다.
DBPostgreSQL양식 정의·서명 이력 같은 유연한 데이터(JSON)와 정형 데이터를 함께 안정적으로 다룹니다.
비동기 처리Celery + Redis알림톡 발송·재발송, 엑셀/ZIP 생성처럼 시간이 걸리는 작업을 화면과 분리해 처리합니다.
인프라AWS 서울 리전 + Docker + GitHub Actions테스트·운영 서버를 같은 구성으로 재현하고, 문서만으로 재배포할 수 있게 합니다.

공고 관련 기술에 Flask가 있어 비교 의견도 드립니다. Flask로도 같은 기능을 만들 수 있지만 인증·권한·관리 기능을 직접 조립해야 해 코드량이 늘고 유지보수자마다 구조가 달라지기 쉽습니다. Flask를 원하시면 같은 금액으로 진행 가능하며, 미팅에서 최종 확정하겠습니다. Node.js·Java는 가능하지만 Python 선호를 고려해 권하지 않습니다.

5. [미정 범위 3] 서버 구성 제안 (하루 약 100명 기준)

구성안내용월 인프라 이용료(예상)의견
A. 표준형 (권장)운영: EC2 t3.small(Docker: 웹·API·작업 큐) + RDS PostgreSQL(자동 백업 7일) + S3(첨부·버전 관리) + CloudWatch 모니터링 / 테스트: EC2 t3.micro 1대약 150,000원DB를 별도 관리형으로 두어 백업·복구가 안전하고, 이용자 증가 시 서버 크기만 올리면 됩니다.
B. 절감형운영·테스트 각 1대에 앱·DB 함께 설치 (Lightsail 등)약 60,000원저렴하지만 서버 장애 시 DB까지 함께 영향, 백업 복구 시간이 깁니다. 법정 서류 보관 시스템에는 권하지 않습니다.
C. 고가용형컨테이너 서비스(ECS) 2대 이상 + DB 이중화(Multi-AZ)약 400,000원 이상무중단에 가깝지만 100명 규모에는 과합니다. 다수 고객사로 확장 시 전환을 권합니다.

6. 카카오 알림톡 연동

  • 알림톡 발송 대행사(예: NHN Cloud, 솔라피 등) API로 연동하며, 작업 배정 시 작업 내용 + 착용 안전장비 + 확인 링크를 발송합니다. 발송·수신·열람 이력이 남습니다.
  • 발송 실패 시 자동 재시도 후 문자(SMS) 대체 발송, 관리자 화면에서 미확인 작업자를 확인하고 재발송할 수 있습니다.
  • 카카오 비즈니스 채널·발신 프로필 등록과 템플릿 검수에 영업일 기준 수일이 걸리므로 착수 1~2주 차에 신청을 안내드리고, 그동안 테스트 발송으로 개발합니다. 발송료·대행사 이용료는 견적에서 제외합니다.

  • 작업자 본인 확인 수준: 링크 + 휴대전화 뒷자리 확인으로 충분한지, 별도 본인인증(PASS 등)이 필요한지
  • 작업자 정보 등록 방식 (협력업체가 직접 등록 / 관리자가 엑셀 일괄 등록), 외국인 작업자 다국어 필요 여부
  • "업체 작업관리자 승인" 이후 작업 시작 조건 — 전원 개인 승인 완료가 필수인지, 일부 미확인 시 예외 처리 규칙
  • 작업허가 승인 단계 수 (담당자 1단계 / 안전관리자 → 현장 책임자 다단계)
  • 긴급작업 알림 대상과 채널 (알림톡 / 문자 / 둘 다), 야간·주말 알림 여부
  • 고객사 납품 이후 운영 시 고객사 보안 정책 (사내망 설치 요구, 데이터 보관 위치, 보안 점검 여부)
  • AWS·도메인·카카오 채널 계정 명의 (권장: 처음부터 발주사 명의로 생성 후 권한 위임)

1. 프로젝트 배경 및 목적

  • 현재 문제: 공장·플랜트 현장에서 작업 배정, 안전 확인, 완료 보고, 각종 안전 서류 작성이 따로 이루어져 기록이 흩어지고 누락 위험이 있습니다.
  • 목표: 작업 배정부터 안전 확인, 완료 보고, 서류 관리까지 한곳에서 처리해 현장 업무를 전산화합니다.
  • 서비스 형태: 관리자 PC 웹 + 작업자 모바일 웹(카카오 알림톡 링크 진입, 앱 설치 없음)
  • 성공 기준: ① 작업 등록 → 알림톡 → 안전 확인·개인 승인 → 업체 승인 → 완료 보고가 끝까지 동작하고 기록이 자동으로 남음 ② 전달받은 서류 양식의 항목 100%가 화면·저장·출력에 대응 (커버리지 리포트) ③ 고객사·현장별 데이터가 섞이지 않음 ④ 발주사가 문서만으로 운영·재배포 가능

3. 기능 요구사항

3.1 인증·권한·기준정보

  • [필수] 관리자·작업관리자·안전관리자·협력업체 계정 로그인, 작업자 일회용 보안 링크 + 휴대전화 뒷자리 확인
  • [필수] 5종 역할별 권한, 고객사·현장별 정보·권한 분리
  • [필수] 현장·협력업체·작업자 정보 관리 (엑셀 일괄 등록), 안전장비 목록 관리

3.2 작업 등록·배정·안전 확인

  • [필수] 작업 등록·배정 (작업 내용, 위치, 일시, 착용 안전장비, 위험 요소)
  • [필수] 배정 시 등록된 전화번호로 알림톡 발송 (작업 내용 + 안전장비 + 확인 링크)
  • [필수] 작업자 모바일: 안전 내용 확인 → 개인별 승인(서명) → 업체 작업관리자 승인 → 작업 시작
  • [필수] 완료 보고 (사진·메모), 작업관리자 확인 후 종료, 전 과정 시각·작성자 자동 기록
  • [필수] 진행 현황 대시보드 (현장별 상태, 미확인 작업자, 지연 작업)

3.3 협력업체 작업허가

  • [필수] 보수작업 신청서·작업자 명단·위험성평가 제출
  • [필수] 담당자 검토 → 승인 / 보완 요청(사유) → 재제출, 단계별 이력 보관

3.4 안전일지·점검서류

  • [필수] TBM(작업 전 안전회의), 교육, 점검 일지와 확인 기록 작성·서명·보관
  • [필수] 양식 정의 기반 화면 생성, 필수 항목 미입력 시 제출 불가, 양식 버전 관리
  • [필수] 문서·첨부자료 엑셀 / 파일 묶음(ZIP) 내려받기 (기간·현장·양식별)
  • [선택] 원본 양식 레이아웃 PDF 출력

3.5 긴급작업·공지

  • [필수] 긴급 보수작업 접수 → 담당자 알림 → 조치 결과 기록
  • [필수] 공지사항(현장별 대상 지정), 비상연락망 — 현장 구성원 조회
